# 用户参与工作流

## 入口

`/#experts` 管理真实任务；`/#history` 保留已导入的 Refine、Expert、Harness 和 Card 历史视图。历史记录不会冒充新一轮产物。

准备任务只复制输入，不调用模型。每次开始都需要用户确认，执行一轮后停止等待。页面展示模型用量所对应的累计费用、本轮费用及待核算请求；这些不是下一轮报价，也不是供应商账单。

## Refine

1. 在工作流程页提供需求记录、参考文稿和当前 Skill 的路径；也可以在会话页选择区间，点击「准备 Refine」。
2. 编辑任务内的当前 Skill 并保存。导入的原文件不覆盖；每轮使用独立冻结副本。
3. 确认费用后开始一轮。后端运行现有固定 Refine 流程，不使用演示结果。
4. 查看阶段产物。候选 Skill 可放入编辑器，用户检查并保存后才用于下一轮。候选不会自动替换当前 Skill。

此入口暂不启动额外的自动诊断实验。失败或重启中断的任务不会自动重试，需要先核查记录。

## Harness

准备任务时导入现有 `MultiCaseOptions` JSON：包含固定案例与回放缓存、原 Card、任务要求，以及 review / boundary 的费用 guard 路径。这里不是历史登记表，也不是生成后的内部 config。

用户可在轮次之间追加评价边界。运行中的输入保持冻结；审查方调用 `ask_user` 时，页面显示问题，用户也可同时追加边界。回答作为工具结果回到同一个审查会话；边界方接收独立标注的用户约束，不把这些文字当作文稿原 Evidence。

等待回答的时间不占执行超时。存在待回答问题时，新模型请求等待；已经发出的请求仍可能返回并计费。回答后继续本轮，不另建审查会话。原先的 Evidence 按需读取、真实引文检查和盲追加 Card 合同保持不变；没有安装 Expert 重跑工具。

每轮仍使用导入时的固定案例和原 Card 生成独立候选，不自动叠加或晋升上轮教材。原 Card、历史回放和预算 guard 不修改。

## 持久化与停止

任务存储在项目的 `.refine-console/workflows/<任务 ID>`：

- `inputs`：导入快照。
- `current-skill.md`：用户可编辑的任务 Skill；修改前保存备份。
- `rounds/<轮次>`：该轮 Skill、运行产物、问题、回答、用户边界和用量记录。
- `state.json`：任务版本、轮次和状态。

接口采用版本号检查，拒绝重复或过期提交。存在未结算费用时不允许下一轮。服务重启后未完成任务标记为中断，不自动恢复付费调用。

「停止本轮」阻止后续模型请求并结束用户等待，不承诺取消已到达供应商的请求，也不撤销已有费用。已停止或失败的任务不能直接续跑。

## 命名兼容

核心入口为 `src/agent-task-runner.ts`，使用 `runAgentTask` 和 `AgentTaskOptions`。`src/pi-task-runner.ts` 仅为历史生成脚本保留旧导入名。第三方包名、插件配置键、`.pi` 存储位置、历史序列化字段和旧实验目录不改名，避免断开既有数据与工具。

## 本地验证

运行 `node --import tsx scripts/check-human-workbench-local.ts` 可启动独立的界面测试服务。它创建临时输入，Refine 和 Harness 均使用本地桩，不调用模型；控制台输出地址与输入目录。测试产物明确标为本地验证，不能用于评价模型效果。

接口与真实运行库的离线测试见 `test/human-workflows.test.ts`、`test/harness-multi-case.test.ts`、`test/web-dashboard.test.ts`。真实运行库测试拦截网络并返回模拟响应，用来验证工具接线、会话连续性和用量记录，不证明真实模型会主动提出合适的问题。
